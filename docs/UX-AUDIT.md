# Аудит UX EasyRoster (v0.5.0, 17.08.2026)

Проведён по живому инструменту с реальными данными (46 рейдеров, 41 с симом, старт сезона 2) и по исходникам `apps/web`.
Каждый раздел: **НУЖНО** — без этого работать неудобно или данные вводят в заблуждение; **МОЖНО** — улучшит, но не блокирует.

Сквозные проблемы (влияют на все разделы) — в конце. Приоритетный список — в самом низу.

---

## 1. Общее: навигация, сложность, статус

**НУЖНО**
- **Переключатель «Сложность рейда сейчас» живёт в трёх местах и в трёх видах**: шапка «Распределения», фильтры сводки BiS (`compact`), карточка персонажа — только читает; в «Лут-таблицах» его нет вовсе, хотя все % там зависят от него. Значение хранится в `localStorage` отдельно от `season.raidDifficulty` в Настройках → в моём браузере оказалось `Mythic`, а в настройках `normal`, и никакой индикации расхождения. → Один глобальный переключатель в сайдбаре (виден всегда), синхронизированный с настройкой; страницы его не дублируют.
- **Порядок меню не соответствует рабочему процессу.** «Ростер → BiS → Лут-таблицы → Распределение → Тир-сет → Настройки». Главный экран лут-ночи («Распределение») — четвёртый. → Две группы: **Подготовка** (Ростер, BiS, Тир-сет) и **Рейд** (Распределение, Лут-таблицы), Настройки внизу.

**МОЖНО**
- Нет глобального индикатора здоровья: устарел db.lua / устарели симы (7 из 41) / WCL без ключей / профиль персонажа 48 дней — видно только на своих страницах. → Маленькая строка статуса в сайдбаре с кликом в нужное место.
- Объяснения (формула приоритета, «как считается», легенда цветов полосы слотов) — почти всегда только в `title=`-тултипе. → Свернутый блок «?» с текстом; легенда статусов (есть / ниже трек / катализатор / нет) — единый компонент везде, где есть цвета.
- Стрелки ↑↓ для переключения предметов в «Распределении» есть, но нигде не подсказаны.

## 2. Ростер

**НУЖНО**
- **Три кнопки синка** («Обновить всё», «Только ростер гильдии», «Персонажи (принудительно)») без объяснения разницы. → Одна кнопка «Обновить» + выпадающее меню с двумя редкими режимами и подписью «когда это нужно».
- **Колонка «В рейде» — кнопка-переключатель «да/нет» по одному клику**, а клик по строке открывает карточку: легко случайно исключить человека из ростера, и это сразу меняет BiS/сим/экспорт в аддон. → Переключатель с подтверждением или отдельный «режим редактирования ростера».
- Ранг показан как «Ранг 0 (0)», пока не импортированы имена из игры; на странице нет подсказки, откуда их взять. → Рядом с заголовком колонки ссылка «Импорт рангов из игры» (сейчас только в Настройки → Интеграция).

**МОЖНО**
- Персонажи с устаревшим профилем (Колдбрю: ilvl «—», 32 дня; Импастар 48 дн) не выделены → бейдж «профиль устарел» и сортировка их вниз.
- Поиск ищет только по имени/классу; нет фильтров по роли/рангу/реалму. Сортировка не запоминается.
- «Вся гильдия» (318) без группировки по рангу; полезно «показать только тех, кто не в ростере, но с рейдовым рангом» (кандидаты на добавление).

## 3. BiS

**НУЖНО**
- **На самом верху — служебная таблица источников** (Icy Veins / WCL / Droptimizer / SimC, кнопки «Обновить (ростер)» / «Все спеки»), затем панель автосима, и только потом сводка по статику. Раз в неделю нужна таблица, каждый день — сводка. → Сводку наверх; источники и автосим — свернутый блок «Данные и симы» (он же нужен на «Тир-сете» — сейчас `SimPanel` просто вставлен дважды).
- **«0%» у 22 персонажей выглядит как поломка.** BiS % = «слотов на макс. треке / всего»; на старте сезона у всех 0–6 %, и метрика ничего не различает. → Ведущий показатель на старте: «потенциал апгрейда» (сумма/среднее лучших % по слотам) и «сколько слотов закрываются из рейда, сколько из M+»; BiS % оставить второй цифрой.
- «WCL … 5 ч назад ⚠» — предупреждение без текста (причина: нет ключей). → Текст «нет ключей → Настройки» прямо в строке.

**МОЖНО**
- Полоса слотов на карточке — без подписей слотов (только тултип). При раскрытии показывается лучший кандидат, но не «что надето» — сравнить нельзя, надо в карточку.
- Кнопка «карточка» и клик по строке делают разное (раскрыть vs открыть) — неочевидно.

## 4. Лут-таблицы

**НУЖНО**
- **Нет переключателя сложности**, хотя проценты претендентов считаются под выбранную сложность (берётся скрытое глобальное значение).
- **Служебный блок «Справочник Raidbots · Проверить обновления · Перекачать» наверху страницы.** → Вниз или в Настройки; на странице — только строка «справочник от … дн» при устаревании.
- Претенденты у предмета — чипы «имя +x% #ранг» без альтернатив; в «Распределении» тот же список показан с альтернативами и разбивкой по трекам. Две страницы на один и тот же расчёт (`bisWanters`), с разной подачей → **объединить**: одна страница «Лут» с двумя режимами — «по инстансу» (нынешние Лут-таблицы, фильтры спека/слот/поиск) и «лут-ночь» (нынешнее Распределение).

**МОЖНО**
- Фильтр по спеке — плоский `select` из 40 спек. → Сначала спеки ростера, остальное под разделителем; фильтр «только предметы, нужные ростеру» (в Распределении он есть, здесь нет).
- Тир-токены показывают `Токен (N)` без списка, кому именно.

## 5. Распределение (главный экран лут-ночи)

**НУЖНО**
- **Сортировка претендентов — по месту в BiS-листе, а не по выгоде.** Пример: «Шаль аманийской призывательницы»: первым идёт Шевч (#1 в слоте, **−0.6 %**), Сэттх (**+3.0 %**) — семнадцатым. Совету нужен порядок по фактическому апгрейду на текущей сложности. → По умолчанию сортировать по %, переключатель «% / незаменимость ▲ / место в листе»; без сима — по рангу и разнице треков.
- **Счётчики вводят в заблуждение.** «29 / 29» красным «нужно» и «макс. −0.6 %»: предмет никому не апгрейд, но выглядит как самый востребованный (сортировка списка предметов — по числу «не имеющих»). → «Нужно» = апгрейд ≥ порога (напр. 0.3 %) или «нет сима и статус нет»; сортировать предметы по «скольким это апгрейд» и максимальному %; отрицательные «макс.» показывать серым «никому не апгрейд».
- **Хилы — «— · нет сима»**: совет не может сравнить хила с ДД. → Для хилов показывать разницу треков/ilvl («Герой 305 vs надето Миф 289») и место в листе крупно, тем же цветовым кодом; сортировать их по этой разнице.
- **Нет отметки «уже выдано сегодня».** История RCLC импортируется кнопкой «История»; во время рейда SavedVariables пишутся только при `/reload`, поэтому автоматизировать полностью нельзя — но после импорта предмет/претендент должен получать бейдж «выдан (дата)».

**МОЖНО**
- Третья колонка (SlotFocus «надето → выпало → лучше») появляется только по клику по претенденту; на широких экранах открывать для первого претендента сразу.
- Тир-токен: в веб-карточке претендента нет «закроет 4pc» (в аддоне есть `tc`) — добавить.
- Компактный статус WoW (аддон/db.lua/история) полезен, но кнопка «Синк в игру» здесь же — риск случайно перезаписать db.lua посреди рейда (безвредно, но лишний `/reload`).

## 7. Карточка персонажа

**НУЖНО**
- **Порядок кандидатов в слоте — по баллу объединения (Icy Veins + сим), а не по симу.** У Дащки в «Голове»: катализаторный тир **−0.6 %** стоит выше M+ шлема **+0.5 %**; в «Шее» рейдовый **−1.2 %** — второй. Для персонажа со свежим симом это дезориентирует. → При наличии сима сортировать по % на выбранной сложности (гайд — как тай-брейк) или явный переключатель «по гайду / по симу» с дефолтом «по симу».
- **Смешение единиц в одном столбце**: «+0.5 %» и «балл 100 / балл 91» (крафт, хилы) выглядят одинаково. → Балл показывать явно другим стилем/подписью («гайд: #1») и не в колонке процентов.

**МОЖНО**
- Источник тир-предмета показан как «• Другое · Миф 318» — должен быть «Тир ← токен: босс».
- Разница ilvl надето ↔ кандидат не показана числом (289 vs «Герой 305» — считать в уме).
- Вкладка «Спека / таланты / правила» = 4 разных блока (рейдовая спека, таланты, Droptimizer, ручные правки) — разбить на подзаголовки; «Ручные правки» показывают `#itemId` вместо названия.
- Кнопки 📌/✕ без подтверждения и без «отменить» — ошибочный ✕ убирает предмет из листа навсегда (виден только в правилах).

## Что уже сделано в 0.5.0: альтернативы по типам контента

Задача: при распределении видеть у каждого претендента **что он может получить в этот слот из другого контента сезона и сколько это даст**, чтобы отдавать предмет тому, кому иначе слот не закрыть.

- **Движок** (`computeAlternatives`): для каждого кандидата слота — лучшая альтернатива из **M+** (трек ключа), с **другого босса рейда** (трек выбранной сложности + разбивка по трекам), из **Великого тайника** (M+ предмет на треке Миф — сим уже считает M+ на Миф), из **крафта**. Альтернатива всегда из другого источника (не тот же босс), а не тот же предмет.
- **db.lua**: поля `am / ar / av / ak = { i=itemID, p=%, n=источник, pt={трек=%} }`; запись предмета теперь в одну строку — файл 965 КБ вместо 1.7 МБ при том же наполнении.
- **Аддон 0.5.0**: две колонки после «BiS» — **«Альт M+»** и **«Альт рейд»**: `+2.5% ▲1.0` = альтернатива даёт +2.5 %, выпавшее лучше её на 1.0 (зелёный ≥1 — слот иначе не закрыть, жёлтый 0.3–1, серый — заменим, ▼ — альтернатива лучше). Сортировка по колонке = «кому выпавшее даёт больше всего сверх альтернативы». Тултип: предмет, откуда, по трекам, остальные типы (тайник/крафт) и вердикт словами. Для рейдовой альтернативы % берётся для трека выпавшего предмета. Имена предметов дозагружаются асинхронно (раньше при первом показе было `#id`). Опция «Колонки Альт» в настройках RCLC → EasyRoster.
- **Веб**: та же разбивка в карточке претендента («Распределение») и в кандидатах слота (карточка персонажа).
- Ограничения: крафт и тайник с рейдовыми предметами не симятся (`sim/service.ts` кормит SimC только рейдом и M+ сезона) — крафт-альтернатива появляется только из гайдов (балл, не %); хилы без сима видят «есть» и место в листе.
